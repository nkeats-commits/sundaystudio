Build a full-stack web app called WorshipFlow.

WorshipFlow is an AI-powered planning assistant for worship pastors, worship leaders, and church creative teams. The app helps users create thoughtful, biblically grounded worship services by generating worship service flows, song recommendations, liturgy ideas, worship leader speaking moments, and team devotionals based on themes, sermon passages, denomination/tradition, liturgical season, worship style, and church context.

The app should feel clean, warm, pastoral, modern, and professional. It should not feel overly “techy.” The tone should be trustworthy, creative, and ministry-minded.

Core tagline:
“Plan worship with depth, not panic.”

Primary users:
- Worship pastors
- Worship leaders
- Creative arts pastors
- Music directors
- Church planters
- Small church pastors
- Volunteer worship leaders

Primary problem:
Worship leaders often have to plan worship services every week while juggling songs, sermon themes, Scripture, transitions, prayers, volunteer teams, denominational expectations, and pastoral tone. Most tools help with scheduling, but few tools help with the actual pastoral and theological planning of the service.

Primary solution:
WorshipFlow helps worship leaders generate cohesive, biblically thoughtful worship planning content quickly, while still allowing them to edit and personalize everything.

Use React for the frontend, Node/Express for the backend, and a relational database such as PostgreSQL or Supabase if available. Use a clean component-based architecture. Make the app mobile-responsive and desktop-friendly.

Include authentication with email/password. Users should be able to sign up, log in, log out, and have their own saved data.

Use a modern dashboard layout with:
- Sidebar navigation on desktop
- Bottom navigation or collapsible menu on mobile
- Clean cards
- Rounded corners
- Soft shadows
- Large readable typography
- Warm neutral color palette
- Accent colors suitable for a ministry/worship app, such as deep navy, warm gold, soft cream, slate, and muted green

11. AI Generation Behavior

Use an AI API integration placeholder if no API key is available. Structure the app so an OpenAI API key can be added later through environment variables.

Environment variable:
OPENAI_API_KEY

Create backend endpoints for AI generation:
- POST /api/generate/service-plan
- POST /api/generate/liturgy
- POST /api/generate/songs
- POST /api/generate/speaking-moment
- POST /api/generate/devotional

Each endpoint should:
- Validate user authentication
- Pull the user’s church profile if available
- Combine church profile with form inputs
- Build a clear system prompt and user prompt
- Return structured JSON
- Save generation history
- Handle errors gracefully

AI system behavior:
The AI should act as a thoughtful worship pastor, liturgist, and theological assistant. It should be helpful, pastoral, biblically grounded, and sensitive to denominational differences. It should not replace human discernment. It should avoid making up song metadata. It should clearly indicate when something should be reviewed by church leadership. It should generate content that is editable and practical.

AI should avoid:
- Cheesy worship clichés
- Overly dramatic language
- Theologically vague language
- Manipulative emotional language
- Overly academic language unless requested
- Assuming all denominations use the same sacramental language
- Inventing song titles, authors, or CCLI information
- Giving copyrighted lyrics

Important copyright rule:
The app should not generate or reproduce copyrighted song lyrics. It may recommend songs by title and artist/writer, but it should not display full copyrighted lyrics.

19. Example AI Prompt Templates

For service plan generation, use this structure internally:

System prompt:
“You are a thoughtful worship pastor, liturgist, and theological planning assistant. You help worship leaders create biblically grounded, congregation-aware worship services. You are sensitive to denominational traditions, liturgical seasons, theological language, and pastoral tone. You do not reproduce copyrighted song lyrics. You do not invent song metadata. You create practical, editable content that worship leaders can adapt.”

User prompt:
“Create a worship service plan using the following details:
Church profile:
[insert church profile]

Service details:
[insert service builder form data]

Return a structured plan with:
- Service overview
- Worship arc
- Service order
- Song recommendations and placements
- Scripture readings
- Calls to worship
- Prayers
- Transitions
- Communion/baptism/offering/confession elements if selected
- Response moment
- Benediction
- Notes for the worship leader
- Notes for the team
- Theological and pastoral rationale.”

For liturgy generation:
“Generate a [liturgy type] for a [denomination/tradition] church. Theme: [theme]. Scripture: [passage]. Season: [season]. Tone: [tone]. Length: [length]. Make it biblically grounded, natural to speak aloud, and appropriate for the congregation. Avoid clichés and overly dramatic language.”

For song recommendations:
“Recommend worship songs for the following theme and context. Do not include copyrighted lyrics. Do not invent song details. If unsure, say so. For each song, include title, writer/artist if known, suggested placement, why it fits, energy level, pastoral notes, possible transition line, and any theological cautions.”

For worship leader speaking moments:
“Write a short spoken moment for a worship leader. Make it natural, pastoral, and stage-ready. Avoid filler words, clichés, and overly polished language. It should sound like something a real worship leader could say.”

For team devotionals:
“Write a devotional for a worship team based on the following topic, passage, and service context. Include title, Scripture, reflection, application to worship ministry, prayer, and optional discussion questions.”
